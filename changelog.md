### Added

- Skill map on About (#29), replacing the per-branch skill tree columns and phone tabs from #27 with one game-like map you can pan and zoom, based on the prototype the owner approved.
  - Two layouts behind a visitor toggle (`aria-pressed` buttons): **Constellation** (default: a start node in the centre, the four hubs on the diagonals, skills on rings further out, joined by circuit lines that run out along the parent's ray, around a ring arc and out to the child) and **World tree** (start node on top, hubs in a row, branches growing down with the stepped circuit lines). The choice is remembered in `localStorage` (`mochkai:skill-map-layout:v1`, try/catch, synced across tabs) through `useSyncExternalStore`; the server always renders Constellation, and a stored World tree applies right after hydration with no mismatch (`src/lib/skill-map-layout.ts`, `useSkillMapLayout`).
  - Layouts stay pure and are computed on the server for both layouts (`buildSkillMap`, `layoutConstellation`, `layoutWorldTree`, `radialEdgePath`, `treeEdgePath`, `nodeBox`, `fitBoxes` in `src/lib/skill-tree.ts`), with the approved constants (hub ring 130, step 94, wedge 84° narrowed for narrow branches; World tree slot 120, row 92). The fitted box includes every ring and label, and the SVG is server-rendered with that `viewBox`.
  - Round nodes: the start node is the owner's logo redrawn inline (`SkillMapLogo`: no white disc, gamepad silhouette in `glow`, d-pad in `neon`), hubs and skills show icons, and each skill has a rank ring of 3 arc segments lit by rank (`SkillRankRing`; it "unlocks" under `motion-safe:` only). Every skill name shows at all times, drawn in a label layer above the nodes. Each label goes below its node by default; `placeLabels` moves it above or beside the node when it would touch another node's ring or another label (for example "Prompt engineering" on the diagonal AI dev chain), so no name is ever covered. Rank stays in each node's accessible name ("React, Mastered, requires TypeScript"); hubs read "Front end branch, 6 skills" and the start node "Start, 4 branches".
  - Icons: Simple Icons paths for the technologies (LangGraph uses the LangChain logo) and Lucide line icons for the concepts and hubs, inlined in a typed map (`src/lib/skill-icons.ts`, generated from simple-icons 13.21.0 and lucide-static 0.460.0, licence notices kept; no new dependency, nothing loaded at runtime). `profile.json` skills and branches take an optional `icon` key (validated: an unknown name fails the build); a missing icon falls back to a neutral rune glyph.
  - Navigation, hand-rolled on pointer events (`useMapViewport`, maths in `src/lib/map-view.ts`): mouse drag and one-finger drag pan; pinch, Ctrl/Cmd + wheel and the − / + buttons zoom within limits (the buttons sit in the toolbar with Full view and Centre, never over the map); **Full view** fits the whole map and **Centre** (or a double tap / double click on empty space) returns to the start view. A press only selects when it moves less than 6 px, and the click that ends a drag is swallowed. The view is clamped so the map never slides off into empty space, and is re-clamped after a resize or rotation. A press released outside the map (or a lost pointer capture) is forgotten, so it can never make a later hover pan, swallow the next click or turn the next touch drag into a pinch; lifting one finger of a pinch never starts a glide. The frame is a fixed `min(70svh, 40rem)` tall on phones (`min(85svh, 46rem)` from `lg`), with `touch-action: none` on the map only, so the page still scrolls from outside it.
  - Readable text: the map opens at the full view when its 13-unit skill labels render at least 10.5 CSS px, otherwise (phones, tablets) zoomed to that scale and centred on the start node. Below 1280 px the details panel sits under the map, so the map gets the full column width; from 1280 px the panel sits beside it and the map bleeds 80 px into the page margins. Both layouts therefore open on the whole map, readable, from 1024 px up.
  - Keyboard: the nodes are one roving Tab stop (start, then each hub and its skills; arrows, Home and End), focus selects the node and pans it into view, and +, − and 0 zoom and reset while focus is in the map. A visible focus ring is drawn around the focused node.
  - Interaction: mouse hover previews the path back to the start node (lit connectors with a flowing dash, `animate-skill-flow`, under `motion-safe:` only); click, tap or focus selects. The details panel (beside the map from 1280 px, below it on narrower screens) shows the icon, branch, rank pips, "Builds on ...", "Unlocks ..." chips that select that skill and pan to it (scrolling the map back on screen first when the panel is below it), and "Used in N quests" linking to `/projects?tech=`; a hub lists its skills and the start node lists the branches. The quest line is still announced in the hidden polite live region.
  - Reduced motion: zooms and pans are instant, a released drag does not glide, and the path, flow and ring animations are off.
  - Removed `SkillTreeBranchView`, `SkillTreeNodeButton`, `layoutBranch`, `spreadRow`, `edgePath` and the phone tablist.
  - Tests: `src/lib/skill-tree.test.ts` (both layouts: positions, arc and stepped connectors, label boxes and label placement, no label over a node or another label in either layout on the real data, connectors that skip rings, bounds, wedges, paths to the start node, focus order), `src/lib/map-view.test.ts` (fit, start view, zoom limits, clamping, zoom at a point, pinch, reveal, the drag-vs-click threshold, glide decay), `src/lib/skill-map-layout.test.ts`, `src/lib/skill-icons.test.ts`, `src/components/SkillTree.test.tsx` (server render, hydration of a stored layout, toggle, selection, chips, hover path, roving focus, zoom keys and buttons, drag vs click, presses released outside the map and lost captures (only the surface's own; a child's implicit touch capture handing over does not end the gesture), Ctrl + wheel, double tap), updated schema, API and About page tests, and `e2e/skill-tree.spec.ts` (both layouts open on the whole map with every name fully inside the frame and at least 10 px at 1024 and 1280 px; 375 px touch: names at least 10 px and no control over the map, a details chip scrolls the map back into view; drag and touch drag pan without selecting, a multi-step CDP touch drag that starts on a node pans the full finger travel, a real two-finger CDP pinch zooms in and out, Full view, Centre, wheel zoom, keyboard, layout persistence across a reload, page scroll outside the map, reduced motion) plus updated About checks in `e2e/pages.spec.ts` and `e2e/reduced-motion.spec.ts`.

- Arcane backdrop (#11): the client component `ArcaneBackground`, rendered once in the root layout, draws a faint rune circuit (neon diamond nodes joined by stepped traces) on a 2D canvas fixed behind every page. It is decorative (`aria-hidden`, `pointer-events: none`, `-z-10`, no layout shift) and starts drawing after hydration, so it never delays the LCP. With motion allowed the nodes pulse slowly and the circuit scrolls with a gentle parallax (6 % of the page speed); with a fine mouse pointer, nodes and traces near the cursor brighten and drift a few pixels. Touch devices get the ambient pulse only, at 15 fps and with fewer nodes. Under reduced motion it paints one static frame with no loop, parallax or pointer reaction. The frame loop (`startArcaneField` in `src/lib/arcane-field.ts`) runs outside React: `requestAnimationFrame` throttled to 30 fps, paused while the tab is hidden or the canvas is off-screen, device-pixel ratio capped at 2, at most 96 nodes (44 on screens under 640 px or coarse pointers). The canvas only draws the neon ink at 26 % opacity, so text on the bare background keeps WCAG AA (asserted in a unit test). No WebGL and no new dependency.
- Gentle parallax (#11): the client component `ParallaxLayer` (helper `startParallax` in `src/lib/parallax.ts`) moves decorative layers slightly slower than the page (at most 16 px, rAF-throttled, scroll listener attached only while the layer is near the viewport). The new server component `RuneCircuit` (a decorative SVG of stepped traces and rune nodes) uses it behind the Home hero text and, from 1024 px, beside every `PageHeader`. Its opacity is applied to the whole SVG (`HERO_CIRCUIT_OPACITY` 0.12 behind the hero text, `HEADER_CIRCUIT_OPACITY` 0.25 beside headers), so overlapping traces never stack into a brighter tint. The backdrop circuit is only rebuilt when the viewport width changes or it grows taller than the tile, so a mobile address bar showing or hiding never reshuffles it. Off under reduced motion.

### Changed

- **Breaking:** `GET /api/profile` replaces `skills` with `skillTree` (#27). Clients reading the old list of skill groups must switch to the branches described under Added.
- Skill tree review follow-ups (#27): a connector to a skill that skips rows now turns in the gap just below its prerequisite's row, so its horizontal run never crosses under an unrelated node in the rows between; the lit path's glow sits on a wrapper group, so the charge animation's `filter` no longer hides it until the animation ends; the details panel is no longer an atomic live region (the focused button's name already reads the name, rank and prerequisites), and only the quest line ("Used in N quests") is announced, so an arrow press is read once; each branch's node container is a `group` labelled "<Branch> skills"; the unused `Skill` and `SkillBranch` type exports are removed. New tests cover row-skipping connectors and diamond-shaped prerequisites (two paths to one skill), which are not reported as cycles.

- Project detail page: the "All projects" back link uses `size="sm"` with `-ml-3.5` (aligned to the compact size's `px-3.5`). Its old `-ml-3 px-3 py-1.5 text-sm` overrides had no effect, because the default `md` size's `px-5 py-2.5` won.
